## Findings

## F146 — component-less plugin directories are invisible to `add` and `validate` (area: discovery, severity: low)

Test:        A3 / step 9 caveat
ocm version: 0.6.0      opencode: 1.18.31
XDG:         unset
Command:     `ocm add` / `ocm validate` on a marketplace containing
             `plugins/p-one/plugin.json` (not valid JSON) and
             `plugins/p-two/plugin.json` (`{}`) with **no commands/, agents/,
             skills/, plugins/ or mcp.json alongside**; same trees isolated
Expected:    brief 33's manifest requirement is per plugin directory; an
             unreadable plugin.json should be reported wherever the directory
             exists (F71's fix)
Actual:      discovery (`loader/discovery.js`) only reaches a plugin directory
             through a component file, so a manifest-only directory is never
             read: `ocm validate` on the isolated trees exits 0 clean, and
             inside a mixed marketplace the broken manifests are silently
             ignored (the other plugins install normally)
Impact:      an author who ships only a broken plugin.json gets no signal at
             all — the F71/F72 refusals work only once some component exists.
             Users are unaffected (nothing installs either way); it is a
             missing-diagnostic case, not a wrong write
Regression?: no — same behaviour in 0.5.x; visible now only because F71/F72
             made the with-component case report
