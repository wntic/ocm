### S4.3 — the mismatched-legacy-layout observation

With skill-named whole-dir symlinks (`skills/greeting`, `skills/tips` —
not the historical form), the first `ocm list --all` printed:

```

registry upgraded v1 → v2 (…)
folded … last-sync.json into per-marketplace lastSync
ocm-e2e3-alpha (auto)
  …
```

— i.e. the relink **did** happen on disk (containers replaced, mirrors
rendered, verified) but no `relinked skill` lines printed. Cause: the
mapping loop in `src/migrate.ts:109` passes each legacy *entry name* as
the plugin key to `skillMapping`, which then looks for mirrors prefixed
`<entry>--`; with the historical `<plugin>`-named symlinks this lines up,
with any other naming it silently prints nothing. Not reachable from a
real historical install (the pre-spec-03 code always named the link after
the plugin), so recorded as an observation, not a defect. It does show the
mapping output is best-effort and silently absent if a hand-made legacy
layout deviates.

the old→new skill mapping), opencode still resolves everything, and it is
idempotent.
