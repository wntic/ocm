## D4.4 — Case-insensitive filesystem, two plugins differing only in case

Setup: `/tmp` is case-insensitive APFS (verified: `mkdir DIR1` after `dir1`
fails). Built a case-sensitive APFS volume (`hdiutil`, `/Volumes/CSX`) with
git repo `case-mp`: plugins `case-Kit` (desc "Upper case K kit", command
`run.md` = UPPER) and `case-kit` (desc "Lower case k kit", `run.md` = lower).

### A) git URL add (clone lands on case-insensitive cache)

```
$ env HOME=/tmp/ocm-e2e3/home-d2-04 ocm add file:///Volumes/CSX/case-mp
exit=0
--stdout--
cloning file:///Volumes/CSX/case-mp...
installed auto-sync loader (/tmp/ocm-e2e3/home-d2-04/.config/opencode/plugins/ocm-loader.js)
added marketplace "case-mp"
  case-kit (1 commands)
commands and agents are available as /<plugin>:<name> in every project
installed TUI plugin (/ocm in the opencode TUI, restart opencode to activate)
restart opencode to activate
--stderr--
```

On disk: the clone has ONE plugin dir `case-Kit` whose contents are
`case-kit`'s files (git checkout of both paths onto a case-insensitive tree
merged them). Registry: one plugin `case-kit`, `source: "plugins/case-Kit"`,
manifest "Lower case k kit". The `case-Kit` plugin is gone. No warning at
add time. `git status` in the cache is permanently dirty
(` M plugins/case-Kit/commands/run.md`, ` M plugins/case-Kit/plugin.json`).
At `ocm update` time only then warnings appear (local changes discarded;
name/dir mismatch), and update still exits 0.

### B) local-dir add (source on case-sensitive volume, read in place)

```
$ env HOME=/tmp/ocm-e2e3/home-d2-04b ocm add /Volumes/CSX/case-mp
exit=0
--stdout--
installed auto-sync loader (…)
added marketplace "case-mp"
  case-kit (1 commands)
…
--stderr--
  warning: plugin "case-kit": plugin.json name "case-Kit" disagrees with the directory name "case-kit"; the directory name wins — rename the directory or fix plugin.json
  warning: case-kit:run.md conflicts with case-Kit:run.md
```

Registry: one plugin `case-kit` (source `plugins/case-kit`, manifest
"Lower case k kit"). Command link `case-kit:run.md` →
`/Volumes/CSX/case-mp/plugins/case-Kit/commands/run.md` — i.e. the
registered plugin is case-kit but its command serves case-Kit's file
("UPPER $ARGUMENTS"). Conflict detected and warned, but not refused; the
surviving state is cross-wired.

`ocm doctor` on both homes: all green, no flag.

**Verdict D4.4: fail** — silently merged (git variant, no warning at all) /
warned-but-proceeded with cross-wired content (local variant). Defects
D2-F1, D2-F2 below.

## D4.5 — OPENCODE_PURE=1

Home `home-d2-05`, `ocm-e2e3-alpha` added (command `greet-kit:greet`,
agent `greeter`, skill `greeting`, loader + TUI plugin installed).

What PURE does (opencode binary, embedded docs, verbatim):
`OPENCODE_PURE=1: skip external plugins entirely.`

Empirical checks:

- `opencode debug config` with and without PURE: identical —
  command `greet-kit:greet`, agent `greet-kit:greeter`, skills path
  `…/.cache/ocm/links/ocm-e2e3-alpha/skills`, plugin origins list
  `file:///…/plugins/ocm-loader.js`. (debug config lists plugin *origins*
  from config; it does not load them.)
- Loader activity: reset `lastSync` to null, then a headless TUI session
  (expect, ~8 s, OCM_SYNC_INTERVAL_MS=0):
  - without PURE → `lastSync` becomes `{"at":"2026-09-15T17:29:29.087Z","ok":true,…}`
  - with `OPENCODE_PURE=1` → `lastSync` stays `null` — **ocm-loader.js did
    not run; ocm's JS plugins are not loaded.**
- Commands/agents/skills are file/config surfaces, not plugins — unchanged
  under PURE (config-level verification above).
- `/ocm` TUI command: provided by ocm's TUI plugin (an external plugin);
  since PURE skips external plugins entirely, it cannot register. Visual
  confirmation in the TUI command picker could not be automated (TUI
  altscreen not capturable via expect/screen hardcopy) — needs user.

**Verdict D4.5: pass** (CLI/loader-level); `/ocm` picker absence = needs user.

## D4.6 — XDG_CONFIG_HOME set to a non-default location


Everything landed in `$H/.config/opencode/` — **ocm ignores
XDG_CONFIG_HOME**. The XDG dir stayed empty.

opencode itself **does** follow it:

- `HOME=$H opencode debug config` → command `greet-kit:greet`
  (reads `$H/.config/opencode`)
- `HOME=$H XDG_CONFIG_HOME=$H/xdg opencode debug config` →
  `{"command":[],"skills":null}` — the ocm-installed config is invisible
- a probe command dropped in `$H/xdg/opencode/commands/xdg-kit:probe.md`
  is picked up only with XDG set: `{"command":["xdg-kit:probe"]}`

README: no mention of XDG anywhere (`grep -rni xdg README.md docs/` →
nothing; only `src/probe.ts` deletes the var for probes).

**Verdict D4.6: fail** — ocm and opencode disagree: with XDG_CONFIG_HOME
set, ocm reports success while opencode sees none of it. Defect D2-F3.
The README does not state the behavior either way (plan asked to record
the answer + README should state it).

## D4.8 — Unwritable ~/.cache

**A) `.cache` exists, chmod 555:**

```

exit=1
--stdout--
cloning file:///tmp/ocm-e2e3/repos/alpha-src...
--stderr--

```

**B) `.cache` is a regular file:**

```
$ env HOME=/tmp/ocm-e2e3/home-d2-08b ocm add file:///…/alpha-src
exit=1
--stdout--
cloning file:///tmp/ocm-e2e3/repos/alpha-src...
--stderr--
ENOTDIR: not a directory, mkdir '/tmp/ocm-e2e3/home-d2-08b/.cache/ocm/marketplaces'
```

Both: exit 1, nothing written to `.config` (no registry, no loader) — no
partial state. But the errors are **raw node/Bun errors** (`EACCES:`,
`ENOTDIR:`), not ocm-style messages — information-exposure defect D2-F5.

**C) add succeeds, then `.cache` made read-only:** `ocm update` → exit 1
with `failed: cannot access … private, unreachable, or the URL is wrong`
(misleading again — real cause is the read-only cache, D2-F4 family);
`ocm install tip-kit` (already installed, no writes) → exit 0; registry
intact.

**Verdict D4.8: partial** — no partial state in any variant, but raw
EACCES/ENOTDIR errors leak (D2-F5).
