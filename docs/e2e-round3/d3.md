### D1.1b four-form probe (own command `probe-kit:probe`)

Built plugin `probe-kit` in the marketplace copy (commands `probe`, `root`;
scripts/x.sh) + `ocm update` (auto-installed, both commands linked).

First attempt used the plan's `!echo …` form (no backticks). Ground truth
(stored user message): `!echo …` stays **raw text** — not executed. opencode's
documented shell-block syntax is `!`cmd`` (backticks). Rewrote with correct
syntax.

Second run, `opencode run --command "probe-kit:probe" "alpha" "beta"`,
stored user message (sqlite, `part` table — `opencode run --format json` does
not expose the rendered user prompt, the session db does):

```
LINE1: args=[alpha beta] first=[alpha] second=[beta] third=[]
```

plus, as **separate parts**, synthetic Read-tool text with
`<content>1: probe-notes-content-XYZZY-42</content>` and a
`{"type":"file","url":"file:///…/probe-notes.txt"}` part.

Semantics verified:
- `$ARGUMENTS` → all args joined; a single arg containing spaces is
  shell-quoted (`"alpha beta"`), separate args join bare (`alpha beta`).
- `$1`/`$2`/`$3` → positional args, missing → empty.
- `!`echo …`` → executed server-side at render time, stdout replaces the
  block (confirmed: no bash-tool call in stderr, output in prompt text).
- `@file` → path resolved (bare, `./` and absolute forms all resolved to the
  same file) and the content **attached** to the message as file parts +
  synthetic Read transcript; the literal `@path` text remains in the prompt.

Verdict: **pass** — all four forms behave; note the plan's own `!echo`
syntax (no backticks) does not execute, and nothing in ocm's README teaches
the `!` syntax either (see D6.3 notes).

## D1.3 — installed agent for a real turn; installed skill via model invocation

### Agent

`opencode run --agent "demo-kit:reviewer" "review billing.py…"` (exit 0):
stderr warning `! agent "demo-kit:reviewer" is a subagent, not a primary agent. Falling back to default agent` — the run continued with the default agent. Reasonable opencode behaviour, clearly stated.

Real subagent use — `opencode run "use the reviewer agent (subagent) to review billing.py…"`:

```
• Review billing.py Demo-Kit:Reviewer Agent
✗ Review billing.py failed Demo-Kit:Reviewer Agent
Error: Model not found: inherit/.
• Review billing.py General Agent
✓ Review billing.py General Agent
```

The ocm template's own agent (`demo-kit/agents/reviewer.md`, frontmatter
`model: inherit`) **fails when actually invoked as a subagent**:
opencode 1.18.31 resolves `inherit` as provider `inherit`, model ``.
`model: inherit` is a Claude Code-ism; opencode's docs say model is
`provider/model-id` and that a subagent inherits the invoking agent's model
when `model` is unset — the correct authoring form is to omit the field.
opencode's task tool then fell back to a General Agent, so the user still
gets a review, but the ocm-shipped agent never runs. See finding D3-F1.

## D6.1 — README authoring-path read-through (NOT executed; notes only)

Read as a first-time author: Install → repository format → plugin.json →
frontmatter → skills → publish → `ocm add`. Stall points found:

1. **Agent authoring is the weak spot (ties to D3-F1).** The README documents
   agent frontmatter as a field *list* (README.md:144–145) but gives no
   complete agent example, never states the `model` value format
   (`provider/model-id`), and never says a subagent inherits the invoking
   model when `model` is unset. An author who reaches for the familiar
   `model: inherit` (as ocm's own template does,
   template/plugins/demo-kit/agents/reviewer.md:8) ships an agent that fails
   at runtime with `Model not found: inherit/.` — and `ocm validate` passes
   it clean (verified: pristine template validates with 0 errors). This is
   the one place a first-time author following the README + template would
   ship something broken with no warning anywhere.
2. **`renames` is an undefined term.** It appears only inside the
   marketplace.json example (README.md:178) and is never explained anywhere
   in the README. An author copying the example will wonder what it does.
3. **`!` shell substitution is warned about but never taught.** README.md:149
   says a body using `!` shell substitution draws a warning, but the correct
   opencode syntax (`!`cmd`` with backticks) appears nowhere; an author
   writing `!echo …` gets validate's warning yet the block silently does
   nothing at runtime (verified in D1.1). The template ships no `!` example
   either.
4. **"trust-gated" (README.md:104) and "materialized" (README.md:106)** are
   used in the format tree before the Trust and loader sections define them —
   a brief stumble, not a blocker; both are defined later.
5. Everything else reads clean: layout tree → plugin.json example → command
   example (verified loadable) → skill frontmatter subset → marketplace.json
   rules; `ocm add <url>` for publishing is shown in Install and Per-plugin
   install (README.md:273). `$schema` guidance now prevents the classic
   first-run warning.
