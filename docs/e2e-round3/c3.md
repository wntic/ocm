Setup: fresh home `home-c3-01`, add MP-A, install `greet-kit`, verify links,
`rm` the links by hand, re-run `ocm install greet-kit`, judge output +
disk state.


(auto mode materialized both plugins at add time.)

Baseline no-op install right after add (contrast case):


True no-op: no restart notice. Correct per spec 23 §3.

`commands/greet-kit:greet.md` → cache clone, `agents/greet-kit:greeter.md` →
cache clone, skill mirror dir `.cache/ocm/links/ocm-e2e3-alpha/skills/greet-kit--greeting/`

Manual deletion:

```

$ rm -rf "$H/.cache/ocm/links/ocm-e2e3-alpha/skills/greet-kit--greeting"
```

(ls of the three dirs confirmed: empty / only `tip-kit--tips` remaining.)

### The step

```

exit=0
--stdout--
already installed greet-kit@ocm-e2e3-alpha
restart opencode to activate
--stderr--
```

### Disk state after (verified)

All three links re-created:
`commands/greet-kit:greet.md` and `agents/greet-kit:greeter.md` symlinks
pointing into the cache clone are back; skill mirror
`links/ocm-e2e3-alpha/skills/greet-kit--greeting/` is back. Registry
unchanged (`enabled: true`, `installedAt` not bumped, revision
`7774b64…`).

### Verdict: partial

The repair happened and the restart notice printed (§5 notice rule
respected — something was created). But the operation is labeled
`already installed`, which is false: the plugin was NOT installed (its
links were gone) and ocm just repaired three of them. The user cannot
distinguish "nothing to do" from "repaired 3 missing links". Filed as
C3-1 (low).
