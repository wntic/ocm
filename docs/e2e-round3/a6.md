### A10.1 — F22: local changes in the cache clone are discarded with one warning

```
$ env HOME=$H ocm init && env HOME=$H ocm add file:///…/alpha-src   → exit 0 (both)

# dirty the clone:
$ printf 'local scratch note\n' >  …/marketplaces/ocm-e2e3-alpha/untracked-note.txt
$ printf '\nlocal edit\n'       >> …/marketplaces/ocm-e2e3-alpha/plugins/greet-kit/skills/greeting/SKILL.md
$ git -C …/ocm-e2e3-alpha status --porcelain

$ env HOME=$H ocm update                            → exit 0
--stdout--
updating ocm-e2e3-alpha...
  already up to date
--stderr--
  warning: /tmp/ocm-e2e3/home-a6-10/.cache/ocm/marketplaces/ocm-e2e3-alpha has local changes; discarded 1 local change and 1 untracked file (the cache is not an editing surface)
```

Afterwards: `git status --porcelain` **empty**; `untracked-note.txt` gone;
`SKILL.md` restored (no diff vs HEAD). Second update:

```
$ env HOME=$H ocm update                            → exit 0
--stdout--
updating ocm-e2e3-alpha...
  already up to date
--stderr--
(empty)
```

Third update identical — clean clone never produces a "local changes" line.

Verdict: **pass**. Exactly one warning, both changes actually discarded,
second update silent, clean clone silent.

Lens note (low): the warning names *counts* ("1 local change and 1 untracked
file"), not the file paths. A user who left three edits can't tell from the
warning which files were thrown away; the clone was cleaned, so the names are
unrecoverable afterwards. The policy sentence ("the cache is not an editing
surface") is good. Borderline against "naming what was discarded" — counted
as pass, flagged as **a10-n1** (low).

### A10.2 — F40: README background-sync paragraph + behaviour

README.md lines 385–389 (verbatim):

```
The startup sync is fire-and-forget: it serves long-lived sessions, where the
fetch finishes in the background long before it matters. A short-lived
invocation — `opencode run`, `opencode debug config` — may exit before the
sync completes, leaving `lastSync` untouched. `ocm update` is the
deterministic path when a sync must have happened.
```

Behaviour:

```
lastSync before:  {"at": "2026-09-15T16:51:34.982Z", "ok": true, …}
$ cd $H && env HOME=$H opencode debug config         → exit 0
$ env HOME=$H ocm list --all                        → exit 0
ocm-e2e3-alpha (auto)
  source: file:///tmp/ocm-e2e3/repos/alpha-src
  revision: 7774b64
  synced just now
  greet-kit (0.1.0) … tip-kit (0.2.0) …
lastSync after:   {"at": "2026-09-15T16:51:34.982Z", …}   ← unchanged
```

Also with the sync forced (`OCM_SYNC_INTERVAL_MS=0`): a short-lived
`opencode debug config` still leaves `lastSync` untouched — the process exits
before the background fetch finishes, exactly as documented.
`opencode debug config` itself sees ocm's links (`.command` includes
`greet-kit:greet`, `.agent` includes `greet-kit:greeter`), and
`ocm list --all` reports sync status truthfully ("synced just now" — the last
sync was my explicit `ocm update`).

Verdict: **pass** — paragraph present, behaviour matches it, no
contradiction between docs and reality.
