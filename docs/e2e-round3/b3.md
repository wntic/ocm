### opencode.json corruption chain (F2/F3 — investigated to root cause)

During s1-7 ocm warned 3× that opencode.json is not valid JSON. The file
was `{"$schema": "https://opencode.ai/config.json",}` — trailing comma.
Reproduced the chain on a scratch home:

1. ocm writes valid `{}` to opencode.json when the last skills path is
   removed (skills skipped / uninstalled).
2. opencode 1.18.31 `debug config` (i.e. any start) splices `$schema`
   into `{}` **with a trailing comma** → invalid strict JSON:
   `printf '{}' > opencode.json; opencode debug config` →
   `{"$schema": "https://opencode.ai/config.json",}` — reproduced.
3. Every later ocm command then warns and leaves the file untouched, so
   skills paths can no longer be re-added by ocm until the user fixes
   the comma by hand. `ocm doctor` does flag it (`warning …: not valid
   JSON, left untouched — fix it by hand`, exit 0, "0 errors, 1
   warning") but `doctor --fix` does not fix it.

Hand-fixing the comma and running a no-op `ocm update` re-adds
`skills.paths` (repair works, exit 0). See findings F2/F3.

**S1 verdict: PASS** (revision transitions, version changes, file lists,
quiet, json all correct) with findings F1–F3.
