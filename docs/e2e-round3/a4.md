### A4-D1 investigation — the silent first bare update (home-a4-01)

Sequence: add (exit 0) → `search` → `validate` ×4 on broken fixtures →
mutate (nm-three added, nm-one bumped) → bare update:

```
$ HOME=$H ocm update </dev/null
exit=0
--stdout--
--stderr--
```

Zero output on both streams while a change was pending; the registry was in
fact updated (nm-one 0.2.0 recorded) by the sync that followed. Reproduction
attempts, all of which printed the header + warning correctly:

1. home-a4-02: fresh home, add, mutate, bare update → prints.
2. home-a4-03: fresh home, add, `search`, mutate, bare update → prints.
3. home-a4-03: immediate re-run (throttle hypothesis) → prints.
4. home-a4-03: after `ocm validate` on the same-named shared fixture (the one
   remaining difference from a4-01), mutate, bare update → prints.

`src/commands/update.ts:57` prints `updating ${name}...` unconditionally for
every registry marketplace unless `--quiet`/`--json`, and an empty registry
prints "no marketplaces added yet". Silence with exit 0 should be impossible
through that path. Observed once, not reproduced in 4 attempts; recorded as
low-severity intermittent (see final report A4-D1).

**A4-D1 resolution (post-mortem): capture artifact, not an ocm defect.**
`/tmp/ocm-e2e3/logs/out.txt` is shared between concurrent round-3 agents; a
parallel agent's `> $OCM_T/logs/out.txt` truncates the same path another
agent is capturing into. This explains both anomalies I hit while using the
shared path: the "silent" first bare update (my output file truncated before
my `cat`) and a garbled first `ocm doctor` capture that contained another
agent's lines (`took over "big-03" from marketplace "ocm-e2e3-big"` — a
marketplace never added to any a4 home; my registry contains no "big"
string). After switching to unique log paths (`logs/a4-*`), every capture is
clean, including a final re-test in home-a4-01 itself:

```
$ HOME=$H ocm update </dev/null   (home-a4-01, unique log path, nm-two -> 0.9.0)
exit=0
--stdout--
updating nomanifest-mp...
  nm-two   0.3.0 → 0.9.0
--stderr--
  warning: plugin "nm-three": plugins/nm-three/plugin.json is missing — not installed; add one ({ "description": "…" }) and update again
```

Harness note for the orchestrator: agents must not share `logs/out.txt`.
