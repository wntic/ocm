## Harness notes (affect interpretation of the transcript)

- **H1 — rtk wrapper.** This agent's shell wraps some commands (`ls`, `jq`,
  `grep`, `cat`) in an `rtk` formatter that truncates long output. All
  exit-code/stream assertions below were captured raw via the BRIEF `run`
  helper (`cat` of redirect files) and are verbatim. Disk listings were taken
  with rtk-wrapped `ls`; content accurate, formatting simplified. A first
  attempt to hand-edit the registry with rtk-wrapped `jq` produced a
  truncated (invalid) JSON file — caught immediately, restored from backup,
  redone with `command jq` (unwrapped). The corrupt-registry doctor outputs
  below from that window are labelled and are themselves informative.
- **H2 — shared log files.** The BRIEF's example `run` helper writes to
  shared `$OCM_T/logs/{out,err}.txt`. A concurrent agent (a6) overwrote mine
  mid-capture; one warning line referencing `home-a6-01` appeared in my
  captured output. Harness artifact, **not** cross-home leakage by ocm. I
  switched to unique filenames (`a5-out.txt`/`a5-err.txt`) afterwards.
- **H3 — `opencode debug config` does not run the loader sync.** The loader
  fires `void core.syncAll(...)` unawaited; `opencode debug config` exits
  before the pull completes (5/5 attempts left the registry untouched). The
  BRIEF's "force it with OCM_SYNC_INTERVAL_MS=0" via `debug config` is not
  sufficient. I forced the sync with a real (expect-driven, blind) TUI
  session held open ~8 s. See observation O1.

## Fixture defects found before A5.2 could run (shared MP-B `exec-src`)

Both were worked around **in my private copy only**; the shared fixture was
not touched.

### FD1 — MP-B `plugins/notify/mcp.json` uses a pre-1.18 MCP shape (severity: high, blocks the round)

`ocm add` + auto-install of `notify` writes
`mcp.ocm--notify--everything = {"command":"node","args":[...]}` into
`opencode.json`. opencode 1.18.31 refuses to start:

```
$ env OCM_SYNC_INTERVAL_MS=0 HOME=/tmp/ocm-e2e3/home-a5-01 opencode debug config
exit=1
--stdout--
--stderr--
Error: Configuration is invalid at /tmp/ocm-e2e3/home-a5-01/.config/opencode/opencode.json
↳ Expected { readonly "type": "local", ... } | { readonly "type": "remote", ... }, got {"command":"node","args":["-e","console.log('everything mcp placeholder')"]} mcp.ocm--notify--everything
↳ Missing key mcp.ocm--notify--everything.enabled
```

Spec 06-manifests.md:119-126 requires mcp.json to contain "exactly opencode's
`mcp` entry shape" (`{ "type": "local", "command": [...], "enabled": true }`);
the fixture has the old `{command, args}` shape. ocm itself behaves per spec
(verbatim copy). Fixture defect — but it makes every opencode verification
with MP-B impossible until fixed.

### FD2 — MP-B `plugins/notify/plugin/notify.js` has no default export (severity: high, blocks the round)

The fixture uses named exports only (`export const id … export const server =
{…}`). opencode 1.18.31 logs on every start:

```
level=ERROR message="failed to load plugin" path=file:///…/plugins/ocm--notify--notify.js error="Plugin export is not a function"
```

`ocm-loader.js`'s shape (`export default { id, server: async () => {} }`)
loads fine, so the verified shape is a default export. My hand-written
`other.js` initially copied the fixture's broken shape and failed the same
way; `ocm doctor` turned it into 2 errors with a misleading `(ocm update)`
remedy (see A5.2 first attempt below). Fixed both files in my copy:

```
$ cd /tmp/ocm-e2e3/repos/a5-exec-src && git reset --hard 3b80558
# mcp.json → {"everything": { "type": "local", "command": ["node","-e","…"], "enabled": true }}
# plugin/notify.js → export default { id: "notify", server: async () => ({}) }
$ git commit  →  e01cac9 "base: 1.18.31-valid mcp + plugin export shapes"
```
