## A2.3 — F54 name limits (refusal + zero writes)
Fixtures (own area `/tmp/ocm-e2e3/a2-fixtures/`):
- `long-cmd-mp` — plugin `ok-kit`, command file name = 201 bytes
- `long-plugin-mp` — plugin dir name = 70 chars (valid name charset)
- `long-mkt-mp` — manifest name = 65 chars (also copied to a 65-char dir basename for 3b)
- `boundary-200-mp` — command file name = exactly 200 bytes

Byte-compare method: pre-warm bun's runtime cache with a no-op `ocm list`
(bun itself writes `~/Library/Caches/bun/@t@/*.pile` on any invocation — a
runtime artifact, not an ocm write; without pre-warming every comparison
would show a spurious `Library/` diff), then `cp -R $H before` → `ocm add`
→ `cp -R $H after` → `diff -r before after`.

### CASE 1 — 201-byte command file name

```
$ env HOME=$H ocm add /tmp/ocm-e2e3/a2-fixtures/long-cmd-mp
exit=1
stdout: (empty)
stderr:
  plugin "ok-kit".command "ccc…c.md" exceeds 200 bytes (201)
    rename it in the marketplace, then re-run ocm add
diff -r before after → ZERO WRITES
```

One ocm-style error, names offender + limit + next action. PASS.

### CASE 2 — 70-char plugin name

```
$ env HOME=$H ocm add /tmp/ocm-e2e3/a2-fixtures/long-plugin-mp
exit=1
stderr:
  plugin "ppp…p" exceeds 64 chars (70)
    rename it in the marketplace, then re-run ocm add
diff -r before after → ZERO WRITES
```

(Note: a plugin dir with only `plugin.json` and no components is skipped by
discovery with "no plugins found" — my first fixture attempt; the plugin
needs at least one component to be discovered at all. Fixture corrected.)
PASS.

### CASE 3 — over-long marketplace name

Three sub-cases:

3a. manifest `name` = 65 chars, short dir basename → **exit 0**, added as
`long-mkt-mp` (the dir basename). The over-long manifest name is ignored
like an invalid one — this is spec 17's documented behaviour
(`manifestName` honours a marketplace.json name "only when it is already a
valid marketplace name … an over-long one is ignored like an invalid one").
Not a defect; noting because the plan's ">64-char marketplace name → error"
reading would expect a refusal here.

3b. local dir basename = 65 chars:

```
$ env HOME=$H ocm add /tmp/ocm-e2e3/a2-fixtures/ddd…d
exit=1
stderr:
  marketplace "ddd…d" exceeds 64 chars (65)
    add it again with --name <a shorter name>
diff -r before after → ZERO WRITES
```

3c. `--name` = 65 chars: same refusal, exit 1.

### Boundary — exactly 200-byte command name

```
$ env HOME=$H ocm add …/boundary-200-mp   → exit=0, added, link created
  ok-kit:bbb…b.md (207-char link name: "ok-kit:" + 200)
```

Accepted at exactly the limit. PASS.

**A2.3 verdict: PASS.** All three limits refuse with one ocm-style error
naming offender, limit and next action, exit 1, zero writes to the home.
(3a documents ignore-not-refuse for over-long manifest names, per spec.)

The named-limit warning fires; the rest of the update proceeds (fresh-kit

**But the skipped plugin's command leaks into the config:**

```

    loader  core.js (current)
```

**A2.4 verdict: PARTIAL / DEFECT.** The warning and the continue-past-it

→ defect A2-D1 (see final report).
