## F11 — `ocm update` re-prints the full trust block on EVERY run when trust was never decided (area: CLI, severity: med)
Test: Suite 3 / Test 9 (observed on every update)
Command: `ocm update mp-explicit` (marketplace added with non-TTY trust answer; trust.code stays "none"); repeated, including a run where stdout says `already up to date`
Expected: trust question asked at add time and re-asked only when executable components change (Test 15 semantics); an "already up to date" update certainly should not ask
Actual: every update prints to stderr:
```
marketplace "mp-explicit" ships code that opencode will execute:
  ...
trust this marketplace to run code? [y/N/skip]
```
Non-interactively the answer is silently "skipped" (trust.code stays "none"), so this repeats forever. On a TTY it would block every update on a readline.
Root cause: src/commands/trust.ts:91-102 decideUpdateTrust prompts whenever trust.code is "none"; promptTrust (trust.ts:41-52) prints the block BEFORE checking `process.stdin.isTTY`, and "skipped" records no decision.
Impact: warning fatigue + interactive updates nag on every run; combined with F7 the untrusted state is surfaced on essentially every command.
Status: new
