## F1 — Relative-path `ocm add` installs dead symlinks and a cwd-dependent registry   (area: CLI, severity: high)

Test:        Suite 12 / Test 43, case 8
Command:     cd /Users/yegorvorobyev && HOME=$FAKE ocm add ocm-e2e/local-mp
Expected:    valid local marketplace added; links resolve regardless of later cwd
Actual:      "added marketplace \"demo-marketplace\"" exit 0, but registry stores
             `dir: "ocm-e2e/local-mp"` (relative) and command symlinks under
             `.config/opencode/commands/` point at `ocm-e2e/local-mp/plugins/...`
             — relative to the LINK's directory, so they resolve to
             `.config/opencode/commands/ocm-e2e/...` which does not exist.
             `cat demo-kit:tdd.md` → "No such file or directory";
             `opencode debug config` → `commands: []`.
             From another cwd, `ocm update demo-marketplace` prints
             "marketplace \"demo-marketplace\" directory missing (ocm-e2e/local-mp), skipping"
             and still exits 0.
Impact:      a user who adds a local marketplace from its parent directory (or any
             relative path) gets a silently dead install — no commands, no skills,
             no error. Exit code 0 throughout.
Root cause:  path not resolved to absolute at add time (registry `dir` and link
             targets both built from the raw argument)
Status:      new

## F2 — `ocm add` of an inaccessible private repo hangs at git's username prompt in a tty   (area: CLI, severity: med)

Test:        Suite 12 / Test 43, case 10
Command:     (pty) HOME=$FAKE ocm add https://github.com/wntic/ocm-e2e-a7-private.git
Expected:    a clean failure naming the problem (auth), no clone left behind
Actual:      non-tty (GIT_TERMINAL_PROMPT=0): clean — "git clone failed: ...
             fatal: could not read Username for 'https://github.com': terminal prompts disabled",
             exit 1, no clone left. But in a real tty (expect), the process sits
             forever at git's raw prompt "Username for 'https://github.com':"
             with no timeout and no ocm-level context (timed out at 15s).
Impact:      interactive user adding a private/no-access repo sees an apparent hang;
             the prompt is git's, not ocm's, and gives no hint of what to do.
             The non-tty error also wraps raw git stderr without a next action.
Root cause:  clone spawned without GIT_TERMINAL_PROMPT=0 / --no-askpass
Status:      new

## F3 — 200-char plugin name crashes with raw ENAMETOOLONG and leaves a half-registered marketplace   (area: CLI, severity: low-med)

Test:        Suite 12 / Test 43, case 14

             Registry still contains marketplace "a7nasty"; `ocm list` then shows the plugin
             with its components as if installed, though nothing was materialized.
             `ocm remove a7nasty` recovers cleanly (exit 0, no orphan links).
             With names within per-component limits (plugin 62 + command 81 chars, unicode

             (mkdir in materialize/links path)

## F5 — Ctrl-C at the trust prompt leaves marketplace registered, commands linked, but loader not installed   (area: CLI, severity: low)

Test:        Suite 12 / Test 43, case 15
Command:     (pty) ocm add https://github.com/wntic/ocm-e2e-big → at "trust this marketplace to run code?" send ^C
Expected:    either a full rollback or a clearly reported partial state
Actual:      ^C during clone: nothing left (no clone, no registry) — clean.
             ^C at the trust prompt: registry contains "big" (valid JSON), 12 command links live,
             trust stays {'code': 'none'}, but the auto-sync loader and TUI plugin were never
             installed (they are written after the prompt). `ocm list` shows the marketplace as
             healthy; `ocm doctor` does report it ("loader … missing", "not installed (ocm init)"),
             exit 0. ^C mid-`ocm update` (during fetch): registry valid, clone clean, next update
             completes and materializes — no half state.
Impact:      aborting at the prompt yields a marketplace whose commands work but which will never
             auto-sync until the user notices doctor output or re-runs an ocm command that
             reinstalls the loader. Recoverable, but silent in `ocm list`.
Status:      new
