## F1 — `ocm list` shows untrusted executable components with no blocked marker (area: CLI, severity: med)

Test:        Suite 2 / Test 3, step 4
Command:     `HOME=$FAKE ocm add .../local-mp` (answer N), then `HOME=$FAKE ocm list`
Expected:    executable components (plugin JS, MCP) shown blocked — the plan says
             "executable components shown blocked"; earlier smoke run saw no marker.
Actual:      (verbatim)
             ```
             demo-kit (0.1.0)
               agents: reviewer.md
               commands: tdd.md
               skills: code-review
               plugins: notify.js
               mcp: everything
             ```
             No "(blocked)" / "(untrusted)" marker anywhere. Same in `ocm list --all`.
             `ocm info demo-kit` does show `trust  denied`, but its components block
             still prints `plugin ocm--demo-kit--notify.js → .../plugins/ocm--demo-kit--notify.js`
             and `mcp ocm--demo-kit--everything → ... (mcp)` — paths that do not exist.
             `ocm list --json` carries marketplace-level `trust: {code: "denied"}` (data is there).
Impact:      a user who denied trust reads `ocm list` as "notify.js and the everything
             MCP server are installed". The truth (not linked / not installed) is only
             visible in the one-time add warning or by digging into `info`.
Root cause:  list renderer prints component names without consulting trust state;
             info prints target paths without checking existence.
Status:      new

## F8 — Startup sync is fire-and-forget: short-lived opencode runs kill the in-flight git fetch (area: loader, severity: low)

Test:        Suite 2 / Test 7, steps 3–4
Command:     `HOME=$FAKE OCM_SYNC_INTERVAL_MS=0 opencode debug config` (x2, then x3 timed)
Expected:    forced sync pulls alpha (revision 9963b98 → 1a44a0b), lastSync updated.
Actual:      three consecutive `OCM_SYNC_INTERVAL_MS=0 opencode debug config` runs
             (~0.45s each) — alpha lastSync frozen at its old stamp, revision
             unchanged, syncprobe command absent. The local marketplace's stamp DID
             update each run (scan is instant). With a long-lived process
             (`opencode debug wait` + kill after 8s) alpha synced correctly:
             rev 1a44a0b, ok=true, command live on the next start.
Root cause:  loader/ocm-loader.js:9 — `void core.syncAll(...)` fire-and-forget;
             `debug config` exits before the SSH git fetch (~1–3s) completes.
Impact:      for real TUI sessions (long-lived) this is fine; but any short-lived
             opencode invocation never completes a git sync, and gives no indication
             it didn't. Test-methodology caveat first, edge-case bug second.
Status:      new
