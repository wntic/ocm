## F1 — `ocm add` leaves `lastSync`/`revision` null → misleading "sync is stale" hint on every no-match search (area: CLI, severity: med)

Test:        Suite 7 / Test 22, step 5
Command:     `HOME=$FAKE ocm add https://github.com/wntic/ocm-e2e-search` (answer N), then `HOME=$FAKE ocm search zzzznope`
Expected:    no-match message only; marketplace was cloned seconds ago, nothing is stale
Actual:      ```
             no matches for "zzzznope"
               a marketplace sync is stale or failed; run ocm update
             ```
             Registry after add: `"lastSync": null, "revision": null`. Only `ocm update search` fills them; after that the hint disappears for a git marketplace with no other cause.
Impact:      right after a successful add, every empty search tells the user their install is broken and sends them to `ocm update`, which reports "already up to date".
Root cause:  add path does not record lastSync/revision (src/add.ts); the search no-match path prints the hint when any marketplace has lastSync null/!ok.
Status: new
