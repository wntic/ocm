# 13 — Packaging, naming & migration

Depends on: everything. Ships last, but the naming decision is fixed now
because it appears in every user-visible string.

## Naming

**The CLI stays `ocm`. The npm package becomes `@wntic/ocm`.**

Checked on 2026-09-08:

| Name | npm | Notes |
|---|---|---|
| `ocm` | taken | unrelated OpenChargeMap client, last published 2022 |
| `opencode-marketplace` | taken | NikiforovAll's CLI, v0.5.0 |
| `opencode-plugin-manager` | taken | "Managed plugin sources for opencode", v0.1.5 |
| `opencode-hub` | taken | TUI launcher and plugin manager, v1.0.18 |
| `ocmarket`, `ocpkg`, `ocmp`, `opencode-kit`, `opencode-registry`, `ocmarketplace`, `opencode-store`, `plugsmith` | free | |

Alternatives, had a rename been wanted: **`ocmarket`** (free on npm, one
GitHub org squatting the name, reads as "opencode market", six characters),
`ocpkg` (free on npm but five GitHub collisions including OpenCog's),
`opencode-kit` (free on npm, 80 GitHub name matches, long to type),
`opencode-registry` (free, but "registry" oversells a git-clone tool),
`ocmarketplace` (free, unambiguous, too long for a CLI).

Keeping `ocm` is the right call regardless: it is the name already on disk, in
`~/.cache/ocm`, in the registry filename, in the `/ocm` slash command, and in
the muscle memory of the one existing user. A scoped package removes the only
real problem — a collision on `npm install -g` — without touching any of that.
The unscoped `ocm` name on npm is squatted by an abandoned 2022 package; there
is no confusion risk in practice because nobody installs it.

Publishing:

```jsonc
{
  "name": "@wntic/ocm",
  "bin": { "ocm": "./bin/ocm.ts" },
  "publishConfig": { "access": "public" }
}
```

`bunx @wntic/ocm add …` and `bun install -g @wntic/ocm` both give the `ocm`
binary. The repository stays `github.com/wntic/ocm`.

## Runtime

Bun and TypeScript, unchanged. The one constraint worth restating: the three
files installed into the user's opencode config are **plain JavaScript with no
dependencies and no build step**, because opencode imports them raw. Types for
them live in `ocm/core.d.ts`. Nothing in these specs needs a bundler.

The CLI may use Bun APIs freely; `ocm/core.js` may not — it runs inside
opencode's runtime, so it uses only `node:*` builtins.

## Migration from the current installation

One migration, run automatically by any `ocm` command and by `ocm doctor`,
covering everything the earlier phases changed:

| From | To | Spec |
|---|---|---|
| `plugins/ocm-core.js`, `plugins/ocm-ui.js` in the auto-loaded directory | `ocm/core.js`, `ocm/ui.js` | [01](./01-loader.md) |
| `plugins/ocm-registry.json` | `ocm/registry.json` | [02](./02-registry.md) |
| registry `version: 1` | `version: 2`, absolute `source` rewritten relative | [02](./02-registry.md) |
| `tui.json` entry `./plugins/ocm-ui.js` | `./ocm/ui.js` | [01](./01-loader.md) |
| global `~/.cache/ocm/last-sync.json` | per-marketplace `lastSync` in the registry | [08](./08-update.md) |
| skill links `links/<mp>/skills/<plugin>` → the plugin's whole `skills/` dir | `links/<mp>/skills/<plugin>--<skill>/` per skill, with a rendered `SKILL.md` | [03](./03-materializer.md) |
| legacy `ocm--<mp>` container directories under `commands/` and `agents/` | already removed by the current core; keep the cleanup | [03](./03-materializer.md) |

Properties:

- **Idempotent** — safe on a fresh install, safe run twice.
- **Reported** — one line per thing moved, so the user can see what happened.
- **Reversible enough** — nothing is deleted that cannot be regenerated by a
  re-add; the registry is copied, not moved, until the new location is written
  successfully.
- The skill relink changes installed skill *names* from `<skill>` to
  `<plugin>:<skill>`. That is a user-visible break for anyone who referenced a
  skill by name in a project file, so the migration prints the old → new
  mapping and the README documents it as the one breaking change.

   moved, registry upgraded, `tui.json` rewritten, skills relinked under
   namespaced names, old → new mapping printed.

   install.
